# Мини 2 на Linux и Proxmox

Linux-порт того же стенда Мини 2: оригинальная ARM32-прошивка работает на
ARM64-ядре Alpine в QEMU. macOS-файлы и Windows-ветки сохраняются.
Это экспериментальная виртуальная колонка; привязка к аккаунту и полноценная
голосовая работа не подтверждены. Это не эмулятор Станции 2.

## Установка

На Debian/Ubuntu:

```sh
sudo apt install python3 qemu-system-arm adb
git clone --branch linux https://github.com/chelaxian/yandex-station-emulator.git
cd yandex-station-emulator
bash setup_linux.sh
bash qemu/mini2/run_stand_linux.sh
```

Откройте `http://127.0.0.1:8870/` и нажмите запуск. Либо запустите без панели:

```sh
bash qemu/mini2/start_linux.sh
```

`setup_linux.sh` проверяет SHA256 частей runtime. Существующий диск прошивки
не пересоздаётся. Linux bootstrap, LED-файлы и логи находятся отдельно в
`alpine_root-linux/`, `led_sysfs-linux/`, `run-linux/` внутри `qemu/mini2/`.
macOS и Linux используют один диск прошивки — одновременно их запускать нельзя.
На x86_64 применяется TCG, аппаратного ускорения ARM нет.

Проверенный стенд: Debian 12 / Proxmox VE 8.4, x86_64, Python 3.11,
QEMU 9.2, четыре виртуальных CPU и 1 ГБ RAM. Основные службы прошивки,
root ADB, дополнительный SSH по ключу и повторный запуск ВМ проверены.
Другие дистрибутивы и настоящий аудиовывод пока не проверены.

## Доступ и ограничения

Все управляющие TCP-порты привязаны только к `127.0.0.1`:

| Порт | Назначение |
|---|---|
| 8870 | Исходная панель эмулятора |
| 5556 | root ADB гостевой прошивки |
| 8444 | перенаправление гостевого HTTPS/Glagol 443 |
| 2223 | SSH, если явно добавлен Dropbear и публичный ключ |

```sh
adb connect 127.0.0.1:5556
adb -s 127.0.0.1:5556 shell id
python3 qemu/mini2/tools/console.py 'ps' --socket qemu/mini2/run-linux/console.sock
```

Для удалённого просмотра используйте SSH-туннель, например:
`ssh -L 8870:127.0.0.1:8870 user@server`, затем откройте локальный адрес.
Не публикуйте ADB и диагностическую панель в интернет. Панель Linux отклоняет
чужой Origin и POST без `application/json`.

По умолчанию звук направлен в backend `none`, микрофон получает тишину.
Опции `--audio pa` и `--audio alsa` доступны у `start_linux.sh`, но сами по себе
не подключают микрофон и не доказывают слышимый звук. Нативные macOS
CoreBluetooth/AVAudioEngine мосты на Linux не запускаются. Для BLE есть
отдельный мост BlueZ, описанный ниже. Приём объявления телефоном, облачная
привязка и распознавание голоса пока не подтверждены.

PEM-адаптер использует уже опубликованную upstream пару из `keys/` либо
каталог `PEM_SOURCE_DIR`. Свои ключи не добавляйте в Git. В Linux выбранная
пара остаётся в локальном bootstrap с правами 0600 для последующих запусков
Proxmox; в прошивку копируется в tmpfs. `keymaster:false` в статусе означает
отсутствие настоящего TEE, даже если PEM-адаптер работает.

Для необязательного SSH предоставьте свой статический ARM32 Dropbear и
файл **публичных** ключей, затем повторите подготовку при остановленной ВМ:

```sh
LINUX_DROPBEAR_BINARY=/path/to/dropbear \
LINUX_AUTHORIZED_KEYS=/path/to/authorized_keys \
python3 qemu/mini2/tools/prepare_linux.py
```

Приватный SSH-ключ остаётся у клиента. Парольный вход и SSH forwarding
отключены; host keys генерируются внутри диска ВМ. Dropbear не включён в PR.

## Proxmox

После `setup_linux.sh`, от root на узле Proxmox, выберите свободный VMID:

```sh
python3 scripts/proxmox_linux.py 900
qm start 900
python3 qemu/mini2/viewer/server_linux.py --proxmox-vmid 900
# При необходимости автозапуска:
qm set 900 --onboot 1
```

Создание отказывается менять существующий VMID. Скрипт создаёт ARM `virt`
с TCG; диск, NV, kernel и bootstrap подключены через дополнительные аргументы.
При остановке панели выполняется `sync; poweroff` в госте, затем `qm stop`.
Закрытие самой панели не останавливает ВМ.

**Резервное копирование:** runtime лежит вне управляемых дисков Proxmox.
Обычный `vzdump` не включает эти файлы. Сохраняйте всю папку стенда при
остановленной ВМ отдельно; не переносите и не удаляйте её, пока VM config
ссылается на неё. Для удаления остановите ВМ, снимите автозапуск и удалите
только созданную конфигурацию через `qm destroy VMID`; runtime сохраняется.

## Подключение к yandex-station-web v0.1.4

Это необязательный адаптер для отдельного проекта dimap/yandex-station-web.
Сохраните его `profiles.py` и JSON конфигурации перед изменениями.
Скопируйте `mini2_profile.py`, `mini2_yam.py` и `mini2_display.py` из
`integrations/yandex_station_web/` рядом с `profiles.py`, затем добавьте в конец `profiles.py`:

YAM и дисплей: [возможности и ограничения адаптера](integrations/yandex_station_web/README.md).

```python
from mini2_profile import register
register(globals())
```

Добавьте к `speakers` в конфигурации общей панели:

```json
{"id":"mini2vm","name":"Мини 2 — виртуальная","model":"mini2","device":"127.0.0.1:5556"}
```

Панель должна работать на том же сервере, что QEMU. Перезапустите её обычным
способом. Для приблизительного цилиндрического предпросмотра включите
`mini2` в условие `mini` файла `static/model-studio.js`, а имя — в
`MODEL_NAMES` файла `static/renderer-profile.js`. Это не точная CAD-модель.

Проверены состояние, root-консоль, LED-чтение и выбор третьей колонки.
Редактор загрузки, установка YAM, будильники и запись часов отключены;
раскладки других моделей к Мини 2 не применяются. Аккаунт и токены физических
колонок переносить не требуется. Для отката верните сохранённые файлы,
удалите только новую запись и модуль, затем перезапустите общую панель.

## Проверки

```sh
python3 -m unittest discover -s tests -p 'test_linux*.py'
bash -n setup_linux.sh qemu/mini2/start_linux.sh qemu/mini2/run_stand_linux.sh
curl http://127.0.0.1:8870/api/firmware
```

Проверяйте root-доступ и статусы снова после настоящего перезапуска.
Зелёные статусы не подтверждают облачную регистрацию или голосовую работу.

Штатный legacy `adbd` в длительной работе может аварийно завершаться.
Отдельный `adb-linux-watch.sh` сохраняет код выхода и повторяет запуск через
две секунды, даже если bootstrap использует `set -e`; при работающем демоне
дубликаты не запускаются при штатном единственном supervisor. Порог ротации
лога64КБ проверяется между запусками; активный лог может быть больше.
Логи находятся в гостевом tmpfs. Общий ADB server хоста не перезапускается. Адаптер панели
сериализует shell-запросы только Мини2 и разделяет кеш LED сроком1с между
`clock/state` и потоковым чтением, чтобы несколько вкладок не множили запросы.


## Экспериментальный onboarding через Linux BlueZ

Фирменная прошивка уже экспортирует GATT настройки. Виртуальный `btvirt`
недоступен телефону. Новый `qemu/mini2/tools/ble_linux.py` регистрирует эти
GATT-объекты и исходное объявление (включая ManufacturerData) на настоящем
свободном Bluetooth-адаптере хоста. Чтения, записи и уведомления проходят
в гостевую прошивку по D-Bus через локальный ADB forward. Пароли и токены
мост не сохраняет и не выводит в лог. Реального TEE он не добавляет.

```sh
sudo apt install bluez python3-dbus python3-gi
sudo /usr/bin/python3 qemu/mini2/tools/ble_linux.py
```

Нужен включённый свободный адаптер с поддержкой peripheral/advertising и
работающий root ADB на loopback. По умолчанию используются hci0, ADB5556
и локальный порт D-Bus15557; доступны параметры `--adapter`,
`--adb-device`, `--guest-bus-port`. Не публикуйте этот D-Bus forward в сеть.
У процесса должен быть доступ к host system bus и гостевому root bus.
Для восстановления после потери ADB запускайте через systemd с
`Restart=always`, `RestartSec=5` и абсолютным путём к скрипту.

Проверено на Linux: регистрация GATT и ManufacturerData в настоящем BlueZ,
один аппаратный advertising instance, совпадение трёх читаемых характеристик
и offsets с гостевой прошивкой, восстановление после перезапуска ВМ.
Это не подтверждает обнаружение телефоном или привязку аккаунта.
Откройте рядом с хостом «Дом с Алисой» и добавьте Станцию обычным способом.
Если облако отвергнет ключи исходного стенда, локальный BLE-мост этого не исправит.

Для обмена с телефоном по LAN в Proxmox можно оставить NAT как отдельный
управляющий интерфейс и добавить bridged VirtIO NIC. При остановленной ВМ:

1. Установите в **внешний Alpine bootstrap** пакет `iptables` с зависимостями.
2. Сохраните конфигурацию ВМ и `etc/local.d/mini2.start`. Обновите bootstrap
   из текущего `prepare_linux.py`, сохраняя предоставленные SSH-файлы.
3. Используйте `start_linux.py --print-proxmox-args --proxmox-lan` для
   управляющего NIC с MAC `52:54:00:4d:32:02`; добавьте Proxmox NIC в свой
   LAN bridge с MAC `52:54:00:4d:32:01`.
4. Запишите `lan` в `alpine_root-linux/opt/mini2/network_mode` и запустите ВМ.
   DHCP выдаст адрес `wlan0`; управляющий NIC остаётся `10.0.2.15`.
5. Проверьте SSH/ADB через loopback хоста, DHCP, policy route128 и запрет
   TCP22/5555/8099 с LAN. Правила устанавливаются до запуска root-служб.

Гостевой `udhcpc` продлевает аренду, а отдельная таблица маршрутизации
сохраняет ответы управляющего интерфейса после появления LAN default route.
Для отката остановите ВМ, верните сохранённую конфигурацию/boot и `nat`.
Не изменяйте ради эксперимента ключи или сеть физических колонок.

В bootstrap также есть необязательный data-only YAM hook: он создаёт
`/emulator/yam-autostart-supported` и запускает `/data/local/yam/start.sh`
только при наличии файла `/data/local/yam/autostart` и исполняемого скрипта.
Сам YAM этот hook не устанавливает. Вне chroot путь данных —
`/mini2/bkupgrade/data`, потому что `/mini2/data` является абсолютной ссылкой.


### Список Wi-Fi при проводном подключении ВМ

`wpa_supplicant -D wired` не сканирует Wi-Fi: без отдельного адаптера приложение
получает пустой список. Для Linux LAN-режима добавлены `wifi_scan_linux.py`
(реальное сканирование радио хоста через `iw`) и `guest/wpa-lan-proxy.c`
(гостевой UNIX control socket перед штатным wired backend). Это адаптация
настройки для **проводного** транспорта: выбор SSID не подключает ВМ по радио
и не проверяет Wi-Fi-пароль. Переданные PSK мост отбрасывает без записи;
`key_mgmt` для настоящего wired backend остаётся `NONE`. Интернет ВМ — LAN.
Нельзя использовать такой мост для проверки правильности пароля Wi-Fi.

Сборка и подготовка при остановленной ВМ:

```sh
sudo apt install iw gcc-aarch64-linux-gnu
# Результат сборки — локальный runtime, в Git его не добавляйте.
aarch64-linux-gnu-gcc -static -O2 -Wall -Wextra -Werror \
  -o /tmp/wpa-lan-proxy qemu/mini2/guest/wpa-lan-proxy.c
LINUX_LAN_PROXY_BINARY=/tmp/wpa-lan-proxy \
  python3 qemu/mini2/tools/prepare_linux.py
sudo python3 qemu/mini2/tools/wifi_scan_linux.py --interface YOUR_WIFI_INTERFACE \
  --output qemu/mini2/alpine_root-linux/opt/mini2/wifi-scan-results
```

Выберите существующий Wi-Fi-интерфейс хоста. Сканер не меняет его соединение,
адреса или маршруты. Для постоянной работы используйте systemd; сканер
обновляет файл каждые20с с правами0600. Bootstrap включает proxy только
при `network_mode=lan` и наличии исполняемого бинарника. Он запускается
в chroot прошивки, поскольку адреса UNIX-клиентов должны разрешаться там же.
Только имена команд пишутся в tmpfs-лог, аргументы не выводятся.

Живая проверка: непустой `wpa_cli scan_results` и JSON GATT char5 с полями
`ssid`, `signal`, `secure` вместо `[]`. Для диагностического чтения длинного
GATT-значения передавайте корректный `mtu` или читайте частями по `offset`.
Локальные тесты дополнительно проверяют доставку события SCAN-RESULTS,
передачу результатов и отсутствие PSK в backend/логе. Прохождение выбора
сети и облачной регистрации на телефоне требует отдельного подтверждения.


### Повторное подключение iPhone и независимый транспорт

Legacy ADB может аварийно выходить. При использовании его D-Bus forward
Bluetooth-мост тоже терял соединение и перезапускал GATT-сервер. Для длительной
настройки доступен независимый `guest/dbus-control-forward.c`: TCP15558 только
на управляющем гостевом адресе `10.0.2.15` проксируется в гостевой system bus.
На LAN-интерфейсе этот порт также запрещён firewall. Доступ даёт права root
к D-Bus: используйте только loopback-forward QEMU, без публикации в сеть.

```sh
aarch64-linux-gnu-gcc -static -O2 -Wall -Wextra -Werror \
  -o /tmp/dbus-control-forward qemu/mini2/guest/dbus-control-forward.c
LINUX_DBUS_FORWARD_BINARY=/tmp/dbus-control-forward \
  python3 qemu/mini2/tools/prepare_linux.py
# Добавьте --bus-port 15558 к аргументам Linux launcher/Proxmox generator.
sudo python3 qemu/mini2/tools/ble_linux.py --direct-guest-bus --guest-bus-port 15558
```

Гостевой watcher запускает транспорт после появления socket D-Bus. Проверено:
принудительный выход adbd не прервал20последовательных чтений списка сетей,
процесс BLE не перезапустился. Этот тест не подтверждает облачную привязку.
ATT-диапазон0x0100–0x010d теперь стабилен между запусками моста; он должен
быть свободен у вашего BlueZ. Это исключает смену адресов характеристик
из-за динамического распределения при каждом переподключении процесса.

В ходе диагностики iPhone в ATT-трассе наблюдались ответы0x05
Insufficient Authentication / Pairing not supported. Отключение дополнительного
host plugin`vcp` само по себе не устранило проблему; его причинная роль не доказана.
Успех локальных чтений и стабильность моста не означают успешную регистрацию.

Отдельно прошивка отклонила полученный от iPhone пакет настроек сообщением
`Cannot decrypt ble credentials`: исходный PEM-адаптер поддерживал только
RSA PKCS#1v1.5. Добавлена строгая проверка OAEP-SHA1/OAEP-SHA256, без принятия
непроверенного raw-RSA результата и без вывода расшифрованных данных.
Проверены три варианта на искусственных пакетах, зашифрованных опубликованным
публичным ключом стенда. Это ещё не подтверждает, что реальный пакет приложения
зашифрован именно этим ключом. Не переносите ключи физических колонок ради обхода.
